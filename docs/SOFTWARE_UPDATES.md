# 曜核软件更新

在桌面工作台顶部或托盘菜单打开“软件更新”。网页中的“检查模型版本”只查询模型来源，和软件更新分别管理。普通浏览器只能读取软件版本；安装由桌面更新窗口发起。

2.13.0–2.13.4 的旧解压包可能因安装清单格式不兼容而无法就地升级，旧窗口会误报更新繁忙。请按[旧包清单修复说明](USABILITY_RELEASE_GATE.md#已知旧包修复)处理；2.13.3/2.13.4 的后台已兼容，但安装助手仍有同类缺口；2.13.5 起两端均兼容原始 ZIP 清单。网络检查失败不等于缓存包无效，已验证包仍可离线安装；安装条件未满足时显示具体原因。

## 手动与自动

- 手动：检查版本，下载并校验，保存页面中的编辑后选择安装并重启。
- 自动检查默认开启。2.13.5 起，桌面成功显示页面后等待 60 秒再检查；成功后间隔 24 小时，失败按 15 分钟、30 分钟逐次退避，最长 24 小时。计划持久保存，重启不会立即重复请求。手动检查可越过等待时间。无法写入计划时暂停自动请求。
- 自动安装默认关闭，可在软件更新窗口明确开启；开启后后台下载并校验新版本，在主动选择托盘“退出”时安装，不重新打开工作台。
- 点窗口 × 仍然只隐藏到托盘，不触发安装。系统注销、关机不触发自动安装。
- 有曜核后台任务或当前工作区待处理、进行中的协作任务时不强制退出。已接入草稿保护的模型备注、评分、来源和终端设置未保存时拒绝安装；无法确认页面状态也拒绝安装。保存时继续输入的新内容仍保留为未保存。未接入草稿标记的其他编辑器，以及绕过曜核协议的外部程序任务，不应宣称已受本门禁保护。
- 自动下载上限为 50 MiB。更大的包通过手动下载渠道处理，不静默下载。

## 发布渠道与保护

当前使用 NOXEVYR/ai-hub 的候选通道，candidate 是现有更新通道标识；曜核是 AI Hub 的改名升级，不是另一款软件。旧版仅作历史存档，不作为稳定版推荐。2.13.5 起更新清单固定在 `main` 分支的 `updates/candidate.json`；旧客户端仍读取 `feat/aihub-collaboration-2.7.0` 分支，发布时需要单独维护兼容清单。程序只构造本仓库固定提交下的 Windows 包地址；清单不能指定其他域名、任意下载地址或执行命令。

下载校验大小和 SHA-256，解包校验路径、文件白名单及每个程序文件摘要。只替换程序文件，保留 `data`、模型、图库、配置、数据库、运行环境和本机 `AGENTS.md`。本地程序发生未记录修改或文件冲突时停止更新，避免覆盖手工改动。

新 v2 清单同时绑定 Windows/x64、候选通道、包摘要、原始文件清单摘要与构建标识；旧 v1 清单仍可读取。同版本改包不会触发升级，修复应递增版本号。当前仍下载完整程序包，没有启用差异或 Range 下载，也没有差异失败后静默下载全量的路径。

安装使用当前已安装程序中的独立 helper，先确认桌面与后台实例身份，再请求受控退出。安装前备份，逐文件记录替换；失败恢复程序文件，不用旧数据库覆盖现有数据。安装事务保留在 `data/app-updates`，不要在更新过程中手工删除。

## 发布步骤

1. 构建并验证源码和 Windows 包，将程序及包上传到仓库，记录固定提交 SHA。
2. 使用 `python -B tools/update_feed.py --package releases/AI-Hub-v<版本>-Windows-x64.zip --commit <固定SHA> --notes <更新说明> --output updates/candidate.json` 生成清单。
3. 在下一次提交将 v2 清单上传到 main。针对旧客户端，使用同一已验证 ZIP、相同固定提交和 `--legacy` 另行生成 v1 清单，上传到旧分支的 `updates/candidate.json`；不要把 v2 原样复制给不认识该格式的旧客户端。清单指向已经存在的固定包提交，避免循环依赖或先提示一个尚未可下载的版本。
4. 从公开清单回读包大小与摘要，验证检查、下载、替换、重启与自动退出安装。仅通过检查或暂存测试不能认定安装已通过。

2.11.3 及之前的桌面版本没有本更新器，首次升级到 2.12 仍需程序包替换。从 2.12 起可以使用软件内更新入口。

版本比较遵循 SemVer 的预发布顺序，数字标识低于文字标识，文字区分大小写；带前导零的数字预发布标识无效。当前发布工具只生成三段数字版本的候选清单，客户端在提示可下载前拒绝带 `+build` 构建元数据的发布版本。
