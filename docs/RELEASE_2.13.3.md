# 曜核 2.13.3：完整使用流程修复

曜核是 AI Hub 改名升级后的同一款软件。本轮以首次解压、启动、扫描、能力发现和升级恢复的整体可用性为重点。

## 软件更新

- 直接解压 Windows ZIP 后，更新器能识别原始发布清单，并继续逐文件核对摘要；不再要求只有维护安装才有的字段。
- 安装失败显示服务返回的具体原因，常规失败留在更新窗口内，状态轮询不再立即覆盖错误。
- 安装过程中禁用重复操作；检查线程收尾期间不会启动互相冲突的检查或安装。
- 保留包摘要校验、实例身份核对、备份、回滚和私有数据保护。

旧版本运行的仍是旧更新器，下载到新版包不会提前修复正在运行的旧代码。2.13.0 和 2.13.2 可按[清单修复说明](USABILITY_RELEASE_GATE.md#已知旧包修复)先补充兼容字段再继续更新；2.13.1 还有更新器版本不一致问题，应使用完整新版。

## 整体可用性

- 启动时核对服务所属安装目录，防止两份程序使用同一端口时连接错误的工作区。
- 启动器校验实际 Python 版本，并继续寻找可用的本地环境、PATH 或 Python Launcher；无效候选不会阻断后续发现。
- 离线、权限失败和被排除的目录保留历史索引；只有来源遍历完整且文件确实不存在时才移除图库索引，部分扫描失败明确显示。
- Skill 支持有界读取多行简介；公开接口声明超过扫描限额时明确报告不完整，不再静默遗漏。
- 能力目录刷新中或失败时冻结派单，保留文字草稿，成功刷新后恢复操作。
- 报告目录超过单批上限后继续遍历后续条目；扫描中断、失败保留历史，进程重启后重新读取未完成的目录。
- 临时文件预览支持继续检查下一批，失效登记不会挡住后续候选；手动回收只处理当前预览到的条目，执行前重新校验。正式报告、交付产物与长期记忆不参与自动回收。

## 验收与边界

完整流程的发布要求见 [整体可用性验收](USABILITY_RELEASE_GATE.md)。真实发布包升级、独立进程重启、文件占用回滚和合成数据保留分别验证；不把开发目录启动或单元测试通过等同于全部用户环境可用。

程序包不含模型、私人配置、Python 或 WebView2。依赖安装仍需用户电脑满足要求；第三方 Skill/接口发现不代表已验证调用质量、速度或账号权限。
