# 2.13.7 协作记录与记忆候选修复候选

候选源码，不代表已安装或已公开发布。

协作任务、报告/产物、长期记忆、报告来源增加删除预览、确认和恢复。删除的是管理记录，原文件保留；仍在执行的任务不能删除。任务移除后，其成果隐藏，但既有已批准记忆仍保留原来源引用。来源移除后停止扫描，不能通过重新添加路径绕过；恢复须检查目录身份。

项目与报告页面提供“移出列表”及已移出记录恢复，避免只在协作页删除后又从来源索引重新显示。工作环境提供解除配置入口：保存配置备份、清空当前索引来源，不删除工作区、模型、报告、记忆或第三方工具数据；待办/执行任务及扫描期间阻止解除。

重要操作使用应用内确认窗口。预览绑定工作区、对象版本和当前证据；关闭、过期、对象改变或工作区切换后，旧确认不能提交。

## 长期记忆为何为空

接入 MCP、客户端在线、写报告和提交记忆是四个不同步骤。原协议有 memory_propose，但旧任务说明没有明确要求它，报告提交也没有组合记忆候选。因此报告成功不代表共享记忆已经形成。

新 MCP 提供 aihub_report_submit，将正式分类报告与最多五条显式 memory_candidates 原子提交。项目、任务、来源报告和提交客户端由领取证据派生；候选不会自动批准。没有值得长期保留的结论时提交空数组；旧客户端省略该字段仍兼容，界面区分已评估与未声明。

记忆面板显示真实报告、候选和批准数量，并支持从登记报告快捷填写候选。不自动读取、修改或导入 Codex/ZCode/DSH/WorkBuddy 原生私有记忆，不把报告全文自动视为长期约定。

## 接入更新

升级后重新连接工作端的曜核 MCP，使工具列表与初始化指引刷新。AI 开始任务时读取 aihub_submission_schema 与 aihub_memory_search；领取任务后按分配的路径工作，结束时优先调用 aihub_report_submit，最后再完成任务。也可继续使用 artifact_write/register 并附 memory_candidates，或单独 memory_propose 引用报告。

生成器仅影响后续新任务和规则；不会覆盖现有 AGENTS.md、任务说明或原生客户端记忆。已有报告可在记忆面板作为来源手动提交候选，或由获得相应任务授权的 AI 提炼后提交；仍需要用户审核。

## 任务资源与收尾

新增资源登记、本人资源查询和携证据收尾报告三个 MCP 接口。客户端可按任务登记临时页面的会话/页面 ID、进程 PID 与启动时间、回环监听端口、受管临时目录和输出身份。工作区、领取批次和原登记客户端共同绑定；共享、用户资源与正式输出不作为本任务自动收尾项。

任务完成或交接会返回待收尾资源，协作页提供单独页签、任务筛选、分页和证据详情。界面区分“客户端报告已收尾”与“曜核独立核验”；第一版尚未提供浏览器或进程控制，也不执行全局关闭、强杀、物理删除或系统内存预算调度。无法检查时必须保留未检查/待人工状态。只有客户端实际接入这三个接口，后续任务才会形成登记；旧窗口不会自动补录。[协议与接入顺序](TASK_RESOURCE_LIFECYCLE.md)。

验证使用合成工作区及真实 stdio → 本地 HTTP → SQLite 流程。最终安装包、正式安装、实际客户端采用新指引及公开发布的验收分别记录。
