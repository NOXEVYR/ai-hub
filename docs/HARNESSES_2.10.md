# 曜核 2.10：工作端接入中心

工作端是领取任务或接收项目交接的 AI 工具。2.10 保留 Codex、ZCode、DSH、WorkBuddy 四款内置模板，同时支持发现已知本机入口和手动登记其他工作端。注册表按工作环境隔离；添加一种工作端不需要把它伪装成已有四款之一。

## 三种登记方式

在“协作与记忆 → 工具接入”打开工作端接入中心：

1. **内置模板**：选择已有模板，核对名称、入口与接入方式；可以修改登记或停用。
2. **发现本机工作端**：检查有限的 PATH、已知用户安装位置和当前工作环境的应用位置，显示候选入口。选择候选只预填表单，保存后才成为登记记录。
3. **手动添加**：为其他工具填写稳定的唯一标识和显示名称，选择 MCP stdio 或手动规则交接；程序入口、工作目录和原生配置路径均可留空。

发现采用固定的已知命令名候选，包含四款内置工具及 Claude Code、Gemini CLI、OpenCode、Aider。最多检查前 64 项 PATH 和 1,024 个候选路径，不递归扫描磁盘，不通过运行程序识别版本。达到限制时显示结果不完整；未发现不代表没有安装，未知名称仍可手动登记。已知便携安装位置也只检查固定入口。

显示的入口、工作目录和配置路径仅是元数据。缺失路径会明确标记；登记不会创建这些目录、读取配置正文、写入原生配置或启动工具。请只填本机绝对路径，程序入口不能附带参数。

## 标识与保存

- 工作端 `id`：以小写字母开头，仅含小写字母、数字、下划线和连字符，最多 64 字符。`any` 和 Windows 保留名不可使用。已有 ID 保持稳定；同名显示名称不表示同一工作端。
- 显示名称最多 120 字符，备注最多 2,000 字符；不接收控制字符、凭据、启动命令、参数或环境变量字段。备注当前使用单行文本。
- 每个工作环境最多 128 项，包含四款内置模板。未建立托管工作环境时可查看内置模板与发现候选，不能保存自定义登记。
- 新增提交 `revision: 0`，编辑必须带上当前版本。其他窗口先保存后，旧版本会被拒绝；刷新并核对自己的改动后再提交，不覆盖对方变更。
- 工作区切换后，旧草稿不能直接保存到新的根目录，须重新选择并确认。

## 两种交接方式

**MCP stdio**：登记并启用后，为每个实际客户端设置独立 `client-id`，生成本机配置片段。把 command 和 args 分别填写到该工具支持的 MCP 配置位置，再重载连接。客户端必须主动调用曜核协议、领取任务并登记结果。工作端 ID 是类型/路由标识，client-id 是该类型下的实例标识，两者不能互相替代。

**手动规则交接**：用于尚未接入 MCP 的工具，可参与项目目录与说明交接；不生成 MCP 配置、不接受协议心跳或队列领取。将工具自行打开到项目目录，并把交接文件提供给它。

四款内置模板保留已知的规则文件约定：Codex/ZCode/DSH 的 AGENTS.md，以及 WorkBuddy 的 CODEBUDDY.md。自定义工作端只生成 `AIHUB_HANDOFF_<id>.md`；该文件不表示新工具原生支持或自动读取 AGENTS.md。所有规则都是软约束，不构成系统沙箱。

配置片段适用于支持 MCP stdio 的客户端，具体配置格式仍由该产品决定。现有 `tools/configure_harness_mcp.py` 自动合并助手只处理原有 Codex、ZCode、WorkBuddy 配置；DSH 与自定义工作端需按各自实际配置方式接入。新增登记不扩展该助手的原生格式适配范围。

## 状态分别代表什么

| 状态 | 证据与边界 |
| --- | --- |
| 已发现 | 程序入口是存在的普通文件；没有执行它或核验产品版本 |
| 已登记 | 保存过曜核的接入声明；不表示原生 MCP 配置已经写好 |
| 近期连接 | 此工作环境最近 300 秒收到对应客户端心跳；不保证实时在线 |
| 协议调用已验证 | 当前登记与路径身份下，MCP 客户端成功调用过一个曜核业务接口，例如 task_list；不表示模型、Skill 或生成任务已完成 |

“查看接入证据”只读取现有记录，不发起探测命令、不启动第三方软件、不调用模型。能力目录中的 `verification_status: unverified` 与工作端协议调用证据是两层状态：模型接口和 Skill 的实际执行仍需单独验收。

保存编辑、停用/启用、程序入口变化或工作区目录身份变化，会使之前登记版本对应的调用证据失效。保留历史时间不代表当前配置继续通过；重新连接并成功调用业务接口后，才会记录新的证据。

## 停用与历史

停用保留登记、任务、报告、客户端和能力声明历史，但不允许该工作端再接收新协议任务。历史筛选仍可查到它；能力匹配不推荐已停用或手动模式的工作端，也不能向其派单。重新启用需要保存新 revision 并重新核对连接证据。

如果该工作端仍有已领取任务，先完成、交接或由管理界面释放领取，再停用或切换到手动模式。同一服务进程内的登记和任务接入共用门控，避免停用检查与新领取交错。停用不会结束原工具进程或擅自取消其原生任务。

项目创建、协作任务、报告来源和能力目录使用当前登记的工作端集合。报告与能力的历史来源保留；未知名字或一次心跳不会自动新建自定义工作端。

## 本机接口与保存位置

工作端管理仅通过本机 UI API 提供，不加入 MCP 可修改工具列表：

| 接口 | 用途 |
| --- | --- |
| `GET /api/harnesses` | 查看模板、登记和分层证据 |
| `GET /api/harnesses/discover` | 只读发现候选，不登记 |
| `GET /api/harnesses/check?id=<id>` | 查看现有接入证据 |
| `GET /api/harnesses/config?id=<id>&client_id=<实例>` | 生成配置片段；手动模式仅返回交接说明 |
| `POST /api/harnesses/save` | 保存或停用；必须携带当前 `_workspace_root` 和 `revision` |

save 仅接收 `id/name/executable/work_dir/config_path/notes/connection_mode/enabled/revision` 及 UI 根标记。返回记录中的 `registered_executable` 是用户保存的入口，`executable` 可包含内置模板探测到的入口；`user_notes` 是手填备注，`notes` 保留兼容的说明列表。路径状态和 `evidence_key` 用于区分登记元数据与当前证据。

登记存于 `data/harnesses.sqlite3`，按工作区根隔离。业务调用证据保存在协作数据库，真实凭据由原工具自己管理。数据库与 sidecar、父目录拒绝重解析链接，数据库拒绝硬链接。列表与发现不会创建登记数据库；只有用户保存才写入。更新保留整个 data，运行中的 SQLite 用 backup API 备份。

## 验证边界

自动化检查使用临时工作环境、合成入口和隔离服务，覆盖注册隔离、revision 并发、启停与接单、缺失路径、数据库链接保护、发现上限、动态 MCP 路由、UI 草稿及历史筛选。具体执行结果随候选包交付记录提供。尚未据此宣称任意第三方工作端已完成原生配置、实际 UI 操作或模型任务验收。
