# 2.13.10 历史整合：协作接入与源码同步

此版本最初从固定 main `582828a14966506c27d633e022394941762377c3` 整合已封存的协作功能输入，使用数字版本 **2.13.10**、桌面程序集版本 **2.13.10.0**。源码、原生构建、固定 ZIP、本地安装验收与公共发布分别记录；本说明不代表每台电脑已安装，也不代表三款软件已经完成全部实际执行验收。

2026-10-02 已核对 [v2.13.10 正式发布](https://github.com/NOXEVYR/ai-hub/releases/tag/v2.13.10)：Windows 与源码包均为已上传资产，不再是 2.13.2 下载。此前整合说明中的“尚未公开发布”是整合阶段状态，不代表当前渠道。下列构建步骤保留为该版本的历史验收方法；后续候选独立验收。

## 已整合的功能与保护

- 可选 `aihub-execution/1`：冻结原请求及声明，按工作区与账本绑定进行幂等接受、精确发布端领取、持久结果回查和取消意图；来源、执行端与本机所有者分别授权。Hub 不代替合作软件执行原生任务。
- 所有者授权核对列表：在原生“协作接入”窗口分页查看并显式撤销授权，用于核对创建回复丢失或导出失败。列表不返回钥匙、摘要、路径或输入；不能重新导出旧钥匙或自动再建授权。列表失败保留旧页并禁用陈旧选择，读取也纳入退出与更新的忙碌保护。
- 精确安装 MCP：新接入使用 `--install-root` 核对安装、端口与实例，请求绑定头在读取业务正文前校验；旧显式 `--port` 保留兼容。公开身份绑定防止误接另一兼容安装，不作为恶意同用户监听器的安全隔离。
- 分类报告与共享记忆：报告持久提交和重复回查保持；候选需用户批准后才进入共享检索。记忆页首先显示真实统计与待审候选，教学和故障说明默认折叠；不擅读工具原生记忆。
- 完整扫描保护：模型及图库来源预检、严格 IO、扫描失败保留历史、完整来源才清除缺失条目；报告有界续扫和只回收本次明确展示的候选。
- 原生启动与更新：保留安装身份验证、有界 Python 探测、更新并发与错误提示。只有不可变 SDK/Loader 组件可使用安装身份短缓存；原有数据与浏览器 profile 不迁移。profile 路径达到 260 字符时明确拒绝，不能靠换短测试目录掩盖限制。
- 只读 `aihub-interop/1` 快照、资源导航和任务资源记录保持独立边界，不控制合作软件窗口，不自动批准候选或启动生成。

协议与接入边界见 [EXECUTION_PROTOCOL.md](EXECUTION_PROTOCOL.md)、[INTEROP_READONLY.md](INTEROP_READONLY.md)、[MCP_2.7.md](MCP_2.7.md)。完整软件升级及本地验收要求见 [USABILITY_RELEASE_GATE.md](USABILITY_RELEASE_GATE.md)。此前固定候选的单次本地安装验收记录属于该次安装证据，不能代替新候选的构建、ZIP 或三方链路验收。

## 构建与发布验收

先完成源码 Python/Node 回归，再使用固定离线 SDK 运行 `desktop/build.py --test`，验证短目录、深目录组件绑定和候选 EXE 自身的独立入口。新构建必须实际带有 2.13.10.0 版本，并刷新根目录 `AI Hub.exe`；上游旧 EXE 索引不是本候选构建证明。

随后用 `tools/package_release.py` 生成新的数字版本包，核对精确 ZIP 的摘要、白名单和直接解压后的更新基线。在隔离安装中验证真实替换、重启、私有数据保留和受控退出；正式安装与公共发布须另外记录。历史版本说明和固定旧包保持原样。
