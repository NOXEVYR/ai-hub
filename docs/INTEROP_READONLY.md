# 联动描述与能力选择快照：只读接口 v1

协议标识 `aihub-interop/1`，提供只读跨工具快照。源码、固定包、本地安装验证与公共发布分别记录；接口存在不等于已实现映序路由或完成三方实际协作验收。当前候选状态见 [2.13.10 整合说明](RELEASE_2.13.10.md)。

## 可以调用的出口

| 入口 | 用途 | 是否创建任务或执行能力 |
| --- | --- | --- |
| `GET /api/interop/describe` | 读取实际服务实例、工作区绑定修订及已有协议边界 | 否 |
| `GET /api/interop/capability-snapshot` | 固定一条已发布能力的归一化声明与证据 | 否 |
| MCP `aihub_interop_describe({})` | 同一描述出口，经现有 stdio 桥读取 | 否 |
| MCP `aihub_interop_capability_snapshot(...)` | 同一单能力快照，桥绑定当前工作区 | 否 |

两个新增 MCP 读操作不会登记心跳、初始化协作库或写调用证据；不要求把调用方登记成执行工作端。现有写操作继续要求已登记、启用的工作端与原有领取规则。客户端 ID 本来就不是同一操作系统用户下的软件身份认证。

服务仍只监听 `127.0.0.1`。地址从用户配置导出或明确填写，不扫描端口。本机安装目前使用 18765，其他电脑不固定使用此端口。服务未附带可信控制实例时描述标记身份不可用，不由请求正文补造身份。

## 连接与工作区

`describe` 返回 `protocol`、`workspace_root`、`identity`、`workspace` 和 `connection_revision`。`identity` 来自当前 HTTP 服务的公共控制身份，包含 app、实例 ID、安装位置、端口和服务版本；不包含控制令牌。没有服务实例或没有可用托管工作区时不能把描述解释为可派单连接。

工作区绑定修订仅覆盖规范根路径、普通目录身份和托管状态。它不是现有工作区创建预览的完整配置摘要，也不是跨电脑稳定 UUID；根目录替换、切换和服务重启都需重新核对连接。不会读取配置文件正文、环境值或私有工作端配置来计算修订。

快照请求必须提供：

- `capability_id`：已有能力 ID。
- `connection_revision`：刚从描述读取的连接修订。
- `_workspace_root`：当前工作区根；HTTP 调用方显式提供，MCP 桥自动绑定。
- `expected_declaration_sha256`：可选。验证之前已选声明仍相同；不匹配时返回冲突，不以新版声明替代。

未知字段和重复查询参数拒绝，不能把请求中的 identity、headers 或配置当作可信实例上下文。MCP 已绑定的会话在工作区变化后拒绝自动重绑，调用方需要新连接。

## 声明原文和冻结

现有能力发布没有保留最初 `capabilities_json` 的原字节。快照明确使用 `declaration.origin=stored_normalized_declaration`：

| 字段 | 含义 |
| --- | --- |
| `text` | 数据库中该条已验证、归一化声明的完整文本 |
| `encoding` | UTF-8 |
| `bytes` | `text` 编为 UTF-8 的字节数 |
| `sha256` | 对以上精确字节计算 SHA-256 |
| `parsed` | 校验过的声明对象，供输入界面使用 |

调用方保存完整快照和 `text`，对收到的 `text.encode('utf-8')` 验证摘要。不要对 `parsed` 再序列化后声称得到同一原文摘要，也不要把此规则当作跨语言 JSON 规范化标准。

`selected` 保留能力 ID、key、声明客户端、执行工作端类型及发布时间；另有有界工作端元数据、分开的声明/心跳/业务执行证据和 `snapshot_id`。重新发布同 key 保持能力 ID，但声明内容可能改变。旧快照由调用方保存在原轮次中，服务器不存旧声明版本；同 ID 不等于同版本。仅因发布方撤回或重发，不修改已导出的对象。

声明 UTF-8 上限 32 KiB，总响应上限 128 KiB；超过限制或旧库/关联库不可安全读取时明确失败，不截断后声称完整。只读取目标声明和必要的来源元数据，不盘点 Skill、环境或原生会话，也不访问外部服务。

来源文本列在 SQL 取回前限制长度；只接受普通登记表，每个库使用 250 ms 锁等待与 SQL 执行预算。数据库、WAL 和 SHM 的链接或特殊文件拒绝；有 WAL 而无可用 SHM 时失败，不新建旁路文件。读取既有 WAL 会使用 SQLite 的共享读锁，验收要求库/WAL、登记记录及文件集合不变，SHM 的临时读锁槽不作为业务数据。可识别的凭据格式整条拒绝，保留声明摘要的精确字节含义；此接口不读取真实钥匙，也不以过滤规则代替发布方避免填写凭据。

## 当前真实执行边界

现有能力都是 `harness_queue`：`capability_dispatch` 验证输入后创建 queued 任务，工作端主动领取后执行。没有曜核通用直接生成入口、原生任务查询或原生取消接口。

输入 Schema 是曜核支持的受限子集，未知输入拒绝；不能当作任意原工具完整 Schema。发布声明中的 provider/server、质量、速度和成本是来源声明，不是已验证服务地址或测评结论。近期心跳仅表示曾登记，不能证明该客户端实时在线或具有选中能力。

队列按工作端类型路由，不锁定发布声明的客户端实例。实际领取者必须核对技能/接口、输入、依赖、授权和成本。`capability_dispatch` 当前没有声明摘要 CAS 参数，读取快照后直接沿用能力 ID 派单不能保证原声明版本；本轮没有用快照改变这个写接口。消费方需把这项限制显示出来，后续原子选择/派单适配另行实现，不能把“旧摘要查询通过”宣称为执行版本已锁定。

| 需要的操作 | 已有接口与限制 |
| --- | --- |
| 任务状态 | `task_list(task_id)` 查询曜核队列状态，不是原生生成状态 |
| 产物列表 | `artifact_list(task_id)` 查询已登记普通文件，不代表已播放、收录或审核 |
| 报告核对 | `submission_receipt(task_id, submission_id)` 绑定原工作区/客户端，校验原请求指纹和当前文件 |
| 报告恢复 | `report_submit` / `report_outbox_retry` 使用稳定 UUID、有界重试；尚未提交内容要求当前领取权 |
| 任务完成 | 新管理任务默认要求本次领取的分类报告和显式记忆声明；旧任务或 optional 按各自策略 |
| 交接/释放 | `task_handoff` / 管理端 `task_requeue` 只改变领取状态，不停止原生执行 |
| 取消原生生成 | 尚不支持；不能用交接或删除管理记录冒充取消成功 |

报告最多 1 MiB，普通产物最多 64 MiB，位于领取任务分配的 Reports/Outputs/Temp 普通文件目录。目录说明不授予跨应用任意路径读写权。大型媒体留在映序原流程，可提交小型执行报告或交付清单，分别记录映序导入、收件和人工审核。

模型执行、曜核报告登记、曜核任务完成、映序收件、映序审核独立。`correlation_id` 只作追踪，不作为鉴权或共同去重；映序继续使用自己已有的 receipt/idempotency_key。长期记忆候选仍需用户批准，报告不自动上传云端。

## 验收与后续

本轮使用合成工作区与本地 HTTP/stdio 验证：纯读取不创建库、不改任务/声明、实例和工作区变更、同 key 重发的旧摘要冲突、存储/字段/大小拒绝及旧报告兼容。证据放在 `outputs/yingxu-aihub-interop-20261001/snapshot-v1`。

这份小契约让映序固定选型并识别真实边界，尚不代表两产品完成生成、媒体传输或审核联调。下一步按已有推进计划分别做受控调用内核与可选队列适配，再验证请求恢复、超限媒体和部分收件；实际生成服务与预算另行选定。
