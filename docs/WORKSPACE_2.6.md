# 曜核工作区与来源管理（2.6 基础，2.10 工作端登记）

工作环境页统一定义 AI 根目录、资产扫描来源与图库来源。新电脑不预设作者盘符；用户选择自己的位置，然后预览并确认创建。接入已有目录保留原资产、命名和已有 AGENTS.md。

## 新建与接入

1. 在“工作环境”选择新建，或接入已有目录。新建路径必须尚不存在；已有目录必须使用接入模式。
2. 资产来源与图库来源每行填写一个目录。接入模式清空列表表示停止索引该类来源；新建模式留空使用标准目录。
3. 来源体检区分有效、失效、旧联接、根目录外和排除目录。旧联接只提供规范实体路径建议，不自动替换或移动原件。
4. 检查预览，确认后创建标准分区与工作规则，并备份、保存本地配置。扫描或整理期间不能切换。
5. 另行点击开始索引。保存成功、来源有效、扫描成功是不同状态；旧的扫描时间不代表新来源已扫描。

规则文件位于 `00_Management/AIHub/WORKSPACE.md`，清单位于同目录 `workspace.json`。项目任务模板位于 `00_Management/AIHub/Templates/PROJECT_TASK.md`。根目录缺少 AGENTS.md 时创建入口；已有 AGENTS.md 不覆盖，既有约定继续有效。

## 目录分工

| 分区 | 内容 |
|---|---|
| 00_Management | 规则、清单、目录台账与管理记录 |
| 10_Apps | 软件与运行环境 |
| 20_Models | 模型库 |
| 30_Assets | 可复用素材 |
| 40_Projects | 创作项目工作区 |
| 50_Training/Projects | 训练项目，保留原有结构 |
| 60_Workflows | 可复用工作流 |
| 70_Output | 通用工具出图落地区 |
| 80_Knowledge | 可复用知识 |
| 90_Archive | 归档 |

“创建项目工作区”在 `40_Projects/<项目名>` 新建 `Inputs / Work / Outputs / Deliverables`、README、项目规则、任务交接与项目清单。内置 Codex、ZCode、DSH、WorkBuddy 模板；2.10 从当前登记中选择已启用的内置或自定义工作端，只勾选本次需要的工具。Inputs 按规则只读，过程文件放 Work，运行产物放 Outputs，正式交付放 Deliverables。已有同名项目不覆盖；项目 Outputs 自动加入图库来源，之后扫描才产生图片索引。

项目名必须是唯一目录名，拒绝路径穿越、Windows 保留名及尾随点空格。预览不写入，十分钟内有效；配置、上级目录或目标位置变化后必须重新预览。配置保存失败仅回退本次新增且未被他人修改的文件和空目录，保留原文件及备份。

## 工具模板与自定义工作端的边界

安装探测只检查已知入口的文件元数据，不启动程序，不读取会话内容、凭据或全局配置。检测到可执行文件不代表已经接入项目。

- Codex、ZCode、DSH：项目入口为 AGENTS.md，交接文本指向本项目的明确目录。
- WorkBuddy：额外生成 CODEBUDDY.md 作为其原生规则入口。
- 自定义工作端：先在[接入中心](HARNESSES_2.10.md)登记，项目只生成 `AIHUB_HANDOFF_<id>.md`，不推断其原生支持或会自动读取 AGENTS.md。手动和 MCP 模式均可提供项目交接，只有启用的 MCP 模式可接收协议队列。
- Codex 交接说明可提供已核实 CLI 的新会话启动命令；运行前仍需检查本机工具版本和权限提示。
- 现有桌面会话及其他工具已启动的任务不会自动切换目录。需要在工具中打开本项目并交接 TASK_BRIEF.md。

这些规则和手动接入说明是软约束。此版本没有全盘文件写入监控、没有更改 Windows ACL，也没有将外部 AI 放入操作系统沙箱。工具自身提供的权限功能与当前 Hub 接入状态分开显示。不能据此宣称其他 AI 已被强制禁止写到工作区外。

## 图库与旧索引

图库只读取 output_roots，不因某目录在资产 scan_roots 中就收录所有图片。训练验证的 verify_out、samples 等可以单独登记，发现候选只给建议，确认后才加入；数据集、缓存、应用内部数据不作为图库来源，不需要搬动训练原图。

显式接入工作区后，模型与图库列表按当前有效来源显示。旧来源的索引、评分、备注、标签保留；扫描未覆盖某个模型只标记不可用，不删除其个人记录。当前登记且仍指向所选来源的兼容模型入口可以继续显示。切换工作区共用同一本机数据库，不是多用户或多数据库隔离。

## 更新与回退

上述工作区基础最初在应用 2.6.0、桌面壳 2.4.1 提供；当前候选主程序为 2.10.0，桌面壳沿用 2.9.0.0。更新只替换程序文件，保留整个 data、桌面状态及本机规则；先等后台空闲并使用 SQLite backup API 备份数据库。通过托盘退出对应后台后再更新重开；单独关闭窗口会隐藏到托盘，不能完成服务更新。

工作环境和项目创建的配置备份保存在本机 data/workspace-backups；不会进入公开包。回退程序前保留新的配置与规则备份；旧版本不会理解全部新工作区界面，不要让旧版扫描清除保留记录。目录和资产不因回退自动移动。

测试仅使用合成临时目录，包含预览陈旧、真实 Windows 联接、已有规则保留、配置失败回退、来源过滤、图库排除与 HTTP 流程。浏览器自动化连接不可用时只能报告接口及 DOM 测试结果，不能把它们等同于实际页面视觉验收。
