# 模型用途、角色与兼容架构

曜核的模型分类由 `aihub/classification.py` 共用。模型资产列表、筛选和整理预览应使用该结果，不把模型文件所在目录或外部 AI 的整理描述当作已确认分类。

## 独立维度

- 用途 `domain`：图片、视频、语言、音频、视觉工具、用户指定的通用组件、待确认。当前接口保留一个主要用途，以兼容现有客户端。
- 角色 `model_role`：主模型、LoRA、VAE、文本编码器等。VAE 表示组件类型，不表示可跨模型通用。
- 兼容架构 `architecture`：沿用内嵌元数据、架构记录或人工填写。文件名用途建议不会生成或确认兼容架构。
- 所属范围 `scope`：中央模型库、应用私有、训练产物、归档等，与用途独立。

## 用途证据与优先级

1. 用户保存的用途覆盖自动结果，保存在独立 `model_labels` 表；重新扫描不得清除。
2. 已记录的明确角色、模型内嵌架构及现有架构记录优先于普通文件名建议。已有结构证据和已有推断分别保留其来源。
3. VAE、文本编码器、嵌入组件的文件名若包含有边界的明确组件用途，例如 `audio_vae`、`video_vae`、`qwen_image_vae`，可生成 `domain_source=filename` 的建议。已知且明确的家族加组件名也可提供建议，如 `sdxl_vae`、`wan2.1_vae`。不扫描父目录中的模态词，也不因 `audiovisual`、`videographer` 等子串误判；命名同时指向多个用途时不猜测。
4. MiniMaxH3 家族的视频工作流包含音频组件。其明确命名的 `audio_vae` 可建议归为音频，保留原有家族记录；明确内嵌架构和人工用途仍优先。这是组件用途细分，不是对模型兼容性的认证。
5. 无足够证据的 VAE、编码器和嵌入保留为“用途待确认”。“通用组件”只保留为用户可指定的用途，不再作为未知组件的默认去处。

所有结果附带 `domain_evidence`。名称建议应显示“按名称建议·待核验”；未知架构仍显示“未确认”，分类待确认状态继续保留。用途建议不等于真实生成效果、权重结构或跨模型兼容性通过验证。

## 外部 AI 的整理交接

创建工作区只建立目录和工作约定。外部 AI 应分别说明建议用途、角色、兼容架构及证据；在曜核中保存人工修正后，核验模型列表和筛选结果。仅移动文件、编写一份报告或创建分类目录，不代表曜核已经采纳分类。

本次修复不移动或改写模型、不改变路径、不访问在线模型服务、不回填推测架构，也不覆盖人工标签。历史索引读取时即使用新规则；用户保存过的用途仍优先，只有主动重置才重新采用自动建议。

## 回归验证

`python -B -m unittest discover -s tests -p test_classification.py -v`

覆盖朋友机器上的三个 VAE 名称、未知组件、边界和冲突名称、元数据/人工优先级、MiniMax 音频组件、列表用途计数、扫描后标签保留及重置。使用临时数据库和合成记录，不操作用户模型。
