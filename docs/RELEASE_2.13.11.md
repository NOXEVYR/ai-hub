# 2.13.11：派单恢复与整体验收

本版修复整条协作流程中会造成重复任务、资源凭据失效和页面空白的缺口。源码、固定 ZIP、本地安装和公共发布应分别记录；本说明不代替每台电脑或每个模型服务的实际执行验收。

- 普通能力派单支持可选 `request_id`，按工作区、调用方和原请求内容持久去重。回复丢失时恢复同一任务；同编号更换内容拒绝。旧客户端未提供编号时保留原行为。
- 能力页在硬刷新后保留不透明编号与工作区摘要，可以独立回查原任务。能力已撤回、工作端停用或回复格式不完整时，不自动新建任务；地址栏不保存输入、正文或钥匙。同步回执编号仍使用统一导航，返回原页会保留文字草稿和原编号。回查缺库不创建数据库，旧库不迁移或备份。
- 恢复同一次执行认领时，同一事务把该领取人的资源记录绑定到新凭据。其他任务、其他领取人的资源和历史证据保持原样，旧凭据不能清理，新凭据可以继续完成精确收尾。
- 本地 HTTP 服务增加冷启动连接队列，减少同时加载脚本和样式时的连接拒绝；增加真实 TCP 冷启动资产连接回归。
- 校正陈旧的分发与协作文档。三款软件仍各自独立；可选执行协议及候选适配的验收范围明确列出。

正常链路在空配置、中文工作区、两个自定义工作端上验证：UI 预览取消与创建，丢成功回复与能力撤回后的恢复，真正服务进程重启，STDIO 报告重复提交、分类和来源显示，记忆批准前隔离与批准后共享，完成报告门槛，精确临时文件 Windows 回收与正式报告保护。图片、视频、音频和小窗口布局另外通过真实浏览器验证。所有文件与任务为独立合成数据，不是用户资产。

能力发现、钥匙名称、登记、心跳、业务协议调用和模型执行是不同证据。报告仍需要已接入工作端主动提交；不承诺任意 AI 会自动报告或写共享记忆。报告产物默认保留，只有明确登记的到期临时文件进入回收。长路径与原生依赖限制见 [桌面说明](../desktop/README.md)。

发布前须使用固定离线 SDK 验证原生入口、生成新数字版本包，并从最终 ZIP 直接解压复测、核对升级基线。详细发布门槛见 [USABILITY_RELEASE_GATE.md](USABILITY_RELEASE_GATE.md)。
