# 协作记录删除与共享记忆

删除记录不等于删除原文件。管理列表中的任务、报告、记忆和来源可通过删除预览确认后移入已删除视图，并从该视图恢复；审计及引用保留。移除来源撤销其后续扫描授权，恢复仍需原目录身份有效。报告页的“移出列表”仅隐藏索引，可恢复。

来源撤销后，其范围也不会通过既有目录的自动盘点重新出现。另一有效来源或正式成果提交有独立的收录证据，仍可保留对应文档。

正在执行的任务不能删除。先由当前工作端完成或正常交接，再处理记录；界面和后端都会检查。已删任务不能继续领取或提交成果，已删临时产物不参与到期自动回收。批准记忆的来源报告不会被级联删除磁盘文件。

长期记忆的流程为：正式报告 → 显式候选 → 用户审核 → 共享检索。memory_search 只返回未删除的已批准记忆；候选、退役及已删除状态不是可共享知识。

MCP 的 aihub_report_submit 接收 task_id、lease_token、category、title、filename、content 和 memory_candidates。每个候选仅包含 title、content、scope（project 或 workspace），最多五条，来源和项目由服务端推导。候选应表达稳定约定、关键决策或可复用结论，不包含口令、临时状态或整份日志。空数组表示已评估无持久结论；省略声明的旧报告保持未知/未声明。

报告与候选在同一事务提交：候选验证失败不会悄悄留下报告成功、记忆失败的半成品。使用原有 artifact_write/register 时，memory_candidates 可选；memory_propose 保留独立提案入口。审核、删除、恢复、来源授权及实际回收均仅允许用户界面操作，MCP 客户端无这些权限。

移除工作环境只解除本机配置，原文件和分区历史保留。重新接管相同实体目录后可继续访问历史，现有 MCP 会话必须重新连接。正式目录内容、第三方原生历史与私有记忆不由这些按钮永久删除。

管理记录移除不等于资源已收尾，也不会释放浏览器或进程内存。[任务资源页](TASK_RESOURCE_LIFECYCLE.md)单独保留归属、待收尾与客户端证据；共享资源和正式输出不会因移除任务而被清理。
