# 整体可用性与发布验收

功能测试通过，不能替代用户从下载到日常使用的完整流程。以下项目必须记录实际执行结果；未执行、失败、条件跳过分别列出，不可写成“全部正常”。

## 验收对象

- 使用即将交付的最终 Windows ZIP，保留版本、SHA-256、文件清单和测试证据。
- 解压到独立的中文含空格目录，使用空配置、独立端口与合成资产。
- 不用开发目录运行结果代替解压包，不手工补写安装清单来掩盖首次安装问题。
- 源码、安装包、已安装文件、运行进程、服务版本、界面版本分别核对。

## 必查用户流程

| 流程 | 必须验证的行为 |
| --- | --- |
| 首次启动 | 未设置作者环境变量、不存在工作区时启动；缺少 Python/WebView2 时提供可执行的错误提示；不静默创建作者路径 |
| 本地服务 | 正确复用本安装实例；其他安装或其他服务占用端口时不接错数据；启动超时保留准确的进程状态 |
| 工作区 | 预览不写入；创建、中文路径、冲突拒绝、取消、重启持久化、切换来源均有检查 |
| 资产与报告 | 空库、合成混合资产、扫描失败、手动标签保留；用途/角色/架构独立，证据不足不得假定兼容 |
| 能力中心 | 无工作区只读发现、不同工作端来源、空结果和失败提示；发现候选、已登记、可调用和实际执行分别标记 |
| 报告与清理 | 大目录多批续扫、失败保留历史；超过一批的失效临时登记不挡住后续候选；手动回收重验当前预览，正式报告和长期记忆保留 |
| 交互恢复 | 导航切换不显示过期请求结果；表单失败保留草稿；右键定位来自当前条目；错误不被定时刷新抹掉 |
| 软件升级 | 直接解压上一发布包后升级，正常重启、退出后安装不重启、断网复用已验证包、文件占用回滚、私有数据保留 |
| 关闭退出 | × 收托盘；明确退出只停止本安装后台；忙碌/实例不匹配可恢复且不强杀其他应用 |

## 发布门槛

阻断首次启动、读错工作区、数据丢失、无恢复路径的升级失败属于发布阻断项。先修复，再重新打包并复查受影响流程。

自动测试、原生控件离屏渲染、真实进程级升级和人工操作验收分别记录。没有干净 Windows 虚拟机或外部账号时，明确列出依赖安装、第三方模型调用等未验证范围，不把本机通过推广到所有电脑。

## 已知旧包修复

2.13.0–2.13.4 的 Windows ZIP 使用归档文件清单，旧更新器却要求额外的安装字段。这会导致就地升级被拒，并被旧桌面错误地显示为更新繁忙。

2.13.3/2.13.4 仅后台接受原始归档清单，独立安装助手仍要求安装字段；直到 2.13.5 才同时修正两端。原始旧包自主升级失败必须记录，不能以修复过清单的夹具代替。旧程序尚未升级前，可从**独立解压的新包**运行清单修复工具，`--root` 必须指向旧程序所在目录：

```powershell
python -B tools/repair_update_manifest.py --root "D:\Apps\AI-Hub"
python -B tools/repair_update_manifest.py --root "D:\Apps\AI-Hub" --apply
```

先预览再应用。工具仅适用于 2.13.0、2.13.2、2.13.3 和 2.13.4；2.13.1 还存在更新器版本不一致问题，需要使用完整新版，不能仅靠补充清单修复；核对程序文件摘要，拒绝本地程序变更和未完成事务，备份原清单后只补充兼容字段，不移动工作区、不覆盖程序或数据库。修复后可在旧程序中继续更新。不要把新工具复制进旧包的 `tools` 目录，否则会形成清单之外的程序文件。
