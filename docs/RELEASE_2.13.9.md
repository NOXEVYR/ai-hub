# 2.13.9 本地验收候选：配置发现与报告交付

本候选围绕配置与报告的可核实状态改进，尚未公开发布。

- 能力中心枚举曜核进程及 Windows 用户、系统环境的变量名。新自定义名称也进入发现范围；名称与公开接口声明可以关联，无法读取值、判断密钥有效性或自动接入外部服务。持久存在但进程不可见时提示以新环境重启。
- 接口卡片区分声明、近期协议心跳和实际调用。心跳不会显示成生成服务调用验证。
- 新任务默认要求本次领取者提交分类报告及记忆声明后才能完成。简单任务可显式选报告可选，历史任务保留原状态。报告被删除、改动或来自之前的领取批次，都不能作为当前任务完成凭据。
- MCP 报告先安全暂存，网络错误有界重试；稳定提交 ID 防止响应丢失后重复生成文件与记忆候选。暂存不保存领取凭据。进程重启后，重试需要当前有效领取凭据。
- 协作界面分别显示任务报告要求及本机提交队列的待提交、失败、已确认登记状态；重试指引可复制给原工作端，复制不等于已执行。

适用范围是通过新版协议管理的任务。曜核不会劫持外部工具的生成过程、扫描私有钥匙或原生会话；原工作端仍须接入 MCP 或通用命令行提交入口。共享记忆候选仍需用户批准。提交进入本地曜核，不自动上传云端。

协议与边界详见 [环境发现](ENVIRONMENT_DISCOVERY.md)、[报告完成规则](REPORT_COMPLETION.md)、[MCP 交付与重试](MCP_REPORT_DELIVERY.md)。本机替换、最终包和测试证据记录在维护项目中；用户可见界面由实际试用验收。
