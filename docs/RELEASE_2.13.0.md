# 曜核 2.13.0 · 能力中心与上下文交互

右键页面空白处可返回、前进和刷新；模型、工作流、Skill、图库及文件项按当前对象显示路径操作。输入框与选中文字保留系统文本菜单。菜单支持键盘、焦点恢复和视口边缘定位；目录定位由服务重新检查当前来源及真实文件。

能力中心分为 Skill 库、接口与服务、环境与凭据、任务调度。用途和所属工作端是独立维度，可组合筛选；同一能力可有多个用途、多个工作端。Skill 用途按名称与说明启发式归类，可能需要人工判断；无法确认的用途和工具保持待确认。发现记录、配置存在、工作端声明和真正调用证据分别展示；发现不会执行 Skill、模型或接口。

首次使用解释工作区、能力和项目的关系。新建工作区只需先选本机目录，高级来源与目录规则折叠；已有用户保留来源、草稿和预览确认流程。软件不要求固定盘符或固定工作端，也不迁移原文件。模型和 LoRA 仍属于资产管理，创作和生成由独立工具完成。

## 本机来源

- 使用当前用户目录、可用的 CODEX_HOME、已知 Skill 位置及插件缓存元数据发现能力，不依赖作者电脑的路径。
- 在“能力中心 → 发现来源与覆盖范围”可添加其他工具的 Skill 根目录、公开接口声明文件；工具标识可自定义。
- 保存来源具有工作区和版本校验，不会覆盖其他会话的来源修改。移除来源不删除原文件。
- 扫描有条目、深度和文件大小上限，不读取原生会话、密钥文件或插件私有服务器配置；达到上限明确显示发现不完整。
- 环境页仅显示变量名和是否存在，值不进入 API 或网页。重启程序才能获得外部进程新增的环境变量。只有明确声明的关联才用于环境条目的用途与工具分类。

## 声明独立或自定义服务

在自己的配置位置建立 `.capabilities.json` 文件，然后添加类型为“公开接口声明”的来源。它是接入说明，不是可执行脚本；不要在其中写密钥、账号、headers 或带凭据的 URL。

```json
{
  "schema_version": 1,
  "name": "我的生成服务",
  "capabilities": [
    {
      "name": "生成项目镜头",
      "description": "根据文字和参考图生成视频片段",
      "domains": ["video", "image"],
      "provider": "my-service",
      "operation_id": "generate_clip",
      "env_vars": ["MY_SERVICE_API_KEY"]
    }
  ]
}
```

领域支持 image、video、audio、code、document、research、automation。发现后，在所选工作端配置真正的调用接口并通过现有 MCP 能力发布协议登记，才能进入任务交接；不能把安装插件或存在密钥当成已经接通。原生客户端注入而未暴露的工具清单无法靠磁盘扫描完整获取，可通过显式能力声明接入。

## 验证范围

本轮验证覆盖右键事件、键盘与导航、分类筛选、来源并发校验、插件发现边界、配置保护和桌面构建。测试不调用付费生成服务，不改变其他工具的账号、密钥或原始 Skill 文件。具体本机交付和可见界面验收由对应维护记录另行记录。
