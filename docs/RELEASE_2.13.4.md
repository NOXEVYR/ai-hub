# 曜核 2.13.4 候选：多轮审计修复

本候选针对模型证据、索引性能、登记错误、报告分类、更新恢复及 HTTP 边界进行修复。源码、候选包、正式安装、公开发布与真实业务验收分别记录，不能由候选版本号推定已发布或已安装。

## 修复范围

- 模型识别：区分普通 `.bin` 与具有模型证据的文件，保留真实模型、人工标签、历史登记及硬链接身份，不删除归档。
- 首页与模型列表：减少同一请求内重复文件身份读取，不跨请求缓存陈旧文件状态。
- 登记 API：空工作区与损坏登记提供可读错误，不把 Python traceback 发给界面，不覆盖损坏原件。
- 报告来源：分类仅依据所选来源根下的相对路径，父目录名 `Temp`、`Knowledge` 或“报告归档”不污染分类。此分类不授予文件回收权限。
- 更新器：内部损坏的压缩包与网络失败分开提示；缺失事务的锁记录保留并给出恢复指引。
- 服务入口：明确直启日志、进程回执与实例控制文件的职责；大请求使用有界处理返回 413。
- Python 启动：在尝试运行解释器和 py.exe 前检查基本 EXE 结构，损坏的便携 Python 不再挡住后续有效解释器；同时保留 32 位与 64 位候选。此检查不等于完整系统加载器验证。

详细通过项与未验证项以候选交付回执为准。原 soak 中的预期 500 不等于全部 HTTP 成功；本机端口从用户配置读取，不因默认端口重叠而擅自修改。

COOP-00 0.1 是单独的 **DRAFT / 未冻结** 规格与合成夹具包，不作为本补丁的运行时依赖。三方审阅摘要、身份、幂等与逐产物回执后再实现适配；没有因此宣称映序、棱光与曜核已完成真实业务往返。
