# 曜核 2.10.0 候选版

2.10 将固定的四款工作端入口扩展为“内置模板、发现本机入口、手动登记”。主程序与 MCP bridge 为 2.10.0，Windows 桌面壳沿用 2.9.0.0，继续提供系统托盘与受控后台退出。本说明对应候选源码和程序包，不表示已经正式安装或完成原生客户端验收。

## 本次变化

- 新增工作端接入中心。保留 Codex、ZCode、DSH、WorkBuddy 模板，也可登记其他工具的 ID、名称、入口与交接方式；按工作环境隔离保存。
- 本机发现只检查有限的已知入口。发现不登记、不执行程序、不读取原生配置；未知工具可手动添加。
- 区分已发现、已登记、近期连接和成功协议调用证据。“查看接入证据”只读记录；心跳、协议业务调用和模型实际执行分别表述。
- 协作任务、项目交接、报告来源与能力筛选使用动态登记。自定义工具须先由用户登记并启用 MCP 模式，不能由心跳擅自注册。
- 新增编辑 revision 校验和停用机制。停用保留历史；有已领取任务时先完成、交接或释放。自定义项目规则仅使用 AI Hub 专属交接文件。

完整范围、配置方式与安全边界见 [工作端管理](HARNESSES_2.10.md)。[2.9 更新记录](RELEASE_2.9.md) 保留项目报告、能力目录和托盘的历史说明。

## 候选包与升级

[Windows 候选包](../releases/AI-Hub-v2.10.0-Windows-x64.zip) · [源码候选包](../releases/AI-Hub-v2.10.0-Source.zip) · [SHA-256](../releases/AI-Hub-v2.10.0-SHA256.txt)

建议先解压到新的可写目录，建立合成工作环境验证。包内没有真实模型、图库、配置、索引库、原生登录数据或浏览器资料；历史 2.9 候选包与 2.6 发行包继续保留。

升级已有安装时先等待后台空闲，通过托盘退出该安装的桌面与后台，保留并备份整个 `data/` 后替换程序文件。运行中的 SQLite 使用 backup API 备份。重新启动后，重载各客户端的 MCP 连接；已有 bridge 进程不会自动更新。回退程序也应保留新的注册表和历史数据，旧程序不识别自定义工作端不代表这些记录可以删除。

主程序需要 Python 3.9+；MCP bridge 需要 Python 3.10+；原生配置合并助手需要 Python 3.11+。桌面仍需要 Windows x64、.NET Framework 4.8+ 和 WebView2 Runtime；这些运行环境不在包内自动安装。
